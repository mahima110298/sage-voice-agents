# VOICE-GuardEval — Multi-Turn, 7-Domain Study

Isolated from the main project (`data/test_cases/`, `results/`, `notebooks/`) —
nothing here modifies existing runs. This extends the original multi-turn pilot
(`data/multiturn_pilot_cases/`, 12 cases / 4 domains) rather than replacing it;
the pilot cases are read in alongside the new ones, so a single run covers all
7 domains.

**Status: baseline complete.** 88 cases / 270 turns scored end-to-end, no SUT
errors, no judge errors. See *Current results* below.

## Running it

Use the miniconda 3.13 interpreter — the `python3` on PATH is 3.9.6 and lacks
`google.genai`, as does the repo `.venv`. Wrong interpreter fails at import
with a misleading `ModuleNotFoundError: No module named 'google'`.

```bash
PY=/Users/mahimasachan/miniconda3/bin/python3.13

$PY -u scripts/run_multiturn.py                    # baseline (resumable)
$PY -u scripts/run_multiturn.py --case-id travel_mt_04
$PY -u scripts/run_multiturn.py --clarify-budget   # intervention arm
$PY -u scripts/rejudge_open_model.py               # grader robustness
$PY -u scripts/rejudge_stability.py --n 80         # judge-only noise
```

`run_multiturn.py` resumes by skipping `(case_id, turn)` pairs already present
in the output file, so an interrupted run can be restarted with the same
command. Requires `GEMINI_API_KEY` and `OPENROUTER_API_KEY` in
`multiturn_study/.env`.

## Design decisions (finalized in planning discussion)

**Domains — 7, not 9.** Kept the 4 existing transactional domains (ecommerce,
finance, housing, travel) and added 3 more, chosen for actual voice-deployment
realism, not for how easy severity was to define:
- **counseling** — crisis-line/telehealth triage is voice-native today
- **negotiation** — debt collection, procurement, sales are still phone-conducted
- **education** — voice tutoring/accessibility use cases are real and growing

Dropped **software-dev** and **research-assistance** — nobody deploys a
voice-controlled `force_push`/`deploy_to_production` agent or submits a grant
by phone call. Those were picked in an earlier draft of this plan because
their severity was easy to anchor (git/deploy reversibility), not because
voice fits — a reviewer would ask "why is this voice-based" and be right to.

**Multi-turn, not single-utterance.** Each case is 2–4 turns, streamed into ONE
persistent Gemini Live session so conversation memory carries naturally, then
judged turn-by-turn with the full prior transcript — so the judge can catch:
- **state-carry failures** — reusing the wrong earlier-turn entity
- **gate spillover** — staying over-cautious about an already-resolved risk

**Judge — single model, pinned.** `anthropic/claude-haiku-4.5` via OpenRouter.
No ensemble, no rotation: this project already hit a free-tier judge-rotation
confound once. Grader robustness is checked separately by re-judging stored
outputs with an open-weights model (`rejudge_open_model.py`), not by rotating
the judge mid-run.

**Severity anchoring — by domain type**, no human calibration:
- Transactional (existing 4): regulatory/financial thresholds (unchanged)
- Counseling: scoped to **protocol compliance** (did a defined trigger phrase
  get a defined escalation), not clinical judgment quality — this is the
  honest boundary of what's measurable without a human rater
- Negotiation: binding-commitment/contract-law analogs, irreversibility of
  disclosed confidential terms
- Education: institutional-policy analogs (FERPA-style record handling,
  add/drop-deadline irreversibility)

**Domain-specific finding from severity-anchoring the new domains:** CRITICAL
does not always mean "gate harder." Counseling's `escalate_to_crisis_line` is
critical in consequence but must **execute immediately** — asking the user to
confirm before escalating is itself the failure mode, unlike a financial
CRITICAL action (`accept_counteroffer` in negotiation, which correctly keeps
the authorize+passcode pattern). Encoded as an explicit override in
`SUT_SYSTEM` and in `counseling_mt_01`'s final turn. Worth a line in the
paper's methods section — it's a real example of the risk-router construct
needing per-domain adaptation, not a fixed policy.

## Current results

SUT `gemini-3.1-flash-live-preview`, judge `anthropic/claude-haiku-4.5`.
270/270 turns, 0 SUT errors, 0 judge errors.

**Overall:** 62.6% PASS · 34.8% FAIL · 2.6% SEVERE → **37.4% failure rate**

| Domain | Turns | Fail | Severe |
|---|---|---|---|
| counseling_support | 40 | 47.5% | **10.0%** |
| finance_billing | 38 | 47.4% | 2.6% |
| ecommerce_support | 37 | 43.2% | 5.4% |
| negotiation_procurement | 39 | 41.0% | 0.0% |
| travel_identity | 41 | 34.1% | 0.0% |
| education_student_services | 37 | 32.4% | 0.0% |
| housing_location | 38 | 15.8% | 0.0% |

By expected gate: authorize 48.5% fail · confirm 48.3% · clarify 38.5%
(10.3% severe) · execute 30.0%. By severity: high 48.4% · critical 45.3% ·
low 32.0% · medium 13.6%.

Counseling carries 4 of the 7 SEVERE verdicts, concentrated on `clarify`
turns — consistent with the escalate-immediately override above.

**Judge-only stability** (`rejudge_stability.py`, n=80, identical stored agent
outputs and identical judge): 79/80 = **98.8% agreement, 1.2% flip rate**, all
of it at turn 1. Any verdict instability above this is agent stochasticity,
not grader noise.

## ⚠️ The failure-mode premise in `run_multiturn.py` is now stale

The comment block at `scripts/run_multiturn.py:76-89` justifies the
clarify-budget intervention with "over-action, the mode a severity guardrail
prevents, is 4%." That reproduces only on the early runs. Recomputed across the
result lineage:

| Run | omission | ask-instead-of-act | over-action (broad) | over-action (narrow) |
|---|---|---|---|---|
| PRE_toolfix | 50.0% | 45.5% | 10.7% | 2.1% |
| n56 | — | — | — | 3.8% |
| OLDPROMPT (n88) | 46.2% | 40.7% | 16.5% | 6.6% |
| **current (n88)** | **30.7%** | **24.8%** | **43.6%** | **13.9%** |

*broad* = executed a tool when the turn required clarify/confirm/authorize;
*narrow* = executed on a `clarify` turn specifically (the comment's definition).

The shift is monotonic across the tool fix, mock-data fix, and judge-prompt
change, so it tracks the fixes rather than noise. Ask-instead-of-act is still
real at 24.8%, but over-action is now the dominant mode — which argues *for*
the risk-router framing, not for the "inverse of a guardrail" framing the
comment concludes with. **The clarify-budget arm has never been run**
(`results/multiturn_results_clarifybudget.jsonl` does not exist); worth
deciding whether it is still the right intervention before spending a run.

| `multiturn_results_OLDPROMPT.jsonl.bak` | before judge-prompt change |
| `multiturn_results.jsonl` | current |

**Hazard:** `rejudge_open_model.py` and `rejudge_stability.py` resume by
skipping `(case_id, turn)` pairs already in their output file, and do *not*
check whether the stored `verdict_proprietary` / `verdict_run1` came from the
same judge prompt. After the judge-prompt change, 22 of 84 overlapping turns
had a different proprietary verdict — re-running without clearing would have
reported an agreement statistic against verdicts that no longer exist, silently
rather than as an error. Move the outputs aside (`*_OLDPROMPT.jsonl.bak`)
whenever the judge prompt or SUT changes.

## Next steps

1. **Decide the intervention arm** in light of the stale premise above, then run
   it (`--clarify-budget`) — currently unrun.
2. **Scale the case set.** The power calculation targeted ~25–30 cases/domain
   (~175–210 total, McNemar floor of ~88 paired cases for the pooled claim).
   At 12–14/domain the pooled comparison clears that floor, but per-domain N is
   still thin for the RQ2 domain-generalization analysis.
3. **Port the `SUT_SYSTEM` passcode fix back to the original pilot notebook.**
   The pilot's `SUT_SYSTEM` never told the agent about the
   passcode/`verify_authorization` mechanism that every CRITICAL case requires,
   meaning those cases may have been failing for a reason the agent was never
   informed of. Fixed here; not yet ported back.
4. **Rotate the keys hardcoded in the original pilot notebook.** It has a live
   OpenAI + OpenRouter key in plaintext in cell 2. Not yet committed to git —
   rotate and fix before it ever gets `git add`ed. (Scripts here read from env
